# Реальный гладкий родитель на стыке native → LOD

Продолжение [предыдущего этапа](../native-join-2026-10-27/README.ru.md). Там L0 оставался исходной блочной поверхностью на целых страницах, а боковой меш давал только фаску 0.35 блока. Это сохраняло стык, но превращало большую ближнюю область в кубики.

Теперь полоса заканчивается в настоящем упрощённом родителе L0. Запечены все 1024 плитки исходной области Sky_Art_Study (X 0…1024, Z 192…1216); профиль — `fragmentrender-sky/run-water`, пакет `sky-linked-parent`. Исходный `sky-joined-selected` сохранён отдельно.

## Геометрия

* Конформная исходная поверхность сохраняет исходные вершины и индексы. QEM ведёт историю зависимых схлопываний и соответствие каждой исходной вершины конечной вершине родителя.
* Боковой меш содержит координаты родителя на исходных индексах, включая треугольники, которые в конце схлопнутся. Отдельный `.fine` хранит точные целочисленные исходные координаты. Восстановление через `round(parent)` больше не используется для новых пакетов.
* На самом краю повторяется точная геометрия чанка: 2 блока снаружи остаются точными, следующие 12 блоков переходят в родителя. Поле строится по действительно готовым секциям Sodium, учитывает объединение чанков, конечные стороны и внутренние углы. Оно общее для соседних страниц.
* За полосой рисуется компактный по числу треугольников родитель, а не вся исходная сетка с фаской. У самого L0 также есть сглаживание и упрощение, поэтому выбор L0 для страницы возле native больше не возвращает всю страницу к кубикам.
* Контакты с удерживаемыми моделями, водой, стволами и внешние контуры защищены. Проецируемый тонкий снег не блокирует весь склон: его отдельная оболочка гаснет по тому же полю, а материал берётся из исходной колонки. Листва, вода и пещеры не удаляются вместе с мелкой растительностью.
* L1/L2 могут сохранять прежний сертифицированный гладкий меш, если он дешевле или имеет более строгую оценку ошибки. На стыке с чанком связь fine→parent нужна для L0; независимые дальние уровни пока переключаются существующей политикой projected error + hysteresis. Группы из четырёх страниц переключаются целиком.

## Ограничение стоимости

Плотные переходные сетки хранятся на CPU и загружаются на GPU только около готовых чанков. При изменении footprint ненужные GPU-страницы освобождаются. В рендере нет чтения мира или файлов; полные исходные данные проверяются при загрузке пакета. Полностью точным защищённым плиткам отдельный переходный VBO вообще не нужен (203 из 1024 в этом пакете).

Лимит резидентных буферов остаётся 192 МиБ. Проверка декодированной геометрии теперь считает байты вместо произвольного количества индексов. Это не отменяет существующую большую аллокацию старого Voxy: при активном backend его геометрические проходы обходятся, но удаление его инфраструктуры — отдельная работа.

| Сумма треугольников только рельефа | Прежний пакет | Новый пакет |
| --- | ---: | ---: |
| L0 | 2 209 386 | 1 675 872 |
| L1 | 1 614 566 | 1 246 940 |
| L2 | 717 117 | 671 517 |

Это суммы по всей области для каждого уровня, не число видимых треугольников и не результат FPS-теста. На отдельных защищённых плитках новый L0 может быть дороже исходных greedy quads: локальный выигрыш не гарантирован. При этом на CPU остаётся около 82 МиБ примитивных массивов проверенных переходных сеток; это перенос резидентности, а не бесплатная память.

Основную стоимость лесного кадра по-прежнему создаёт удерживаемая геометрия деревьев.

## Материалы и подача

Используется материал Fragment Render, исходный atlas и точечная карта материалов колонок; усреднения текстур в цветные пятна нет. Сохраняется исправление предыдущего этапа: общая атмосфера применяется один раз в финальном composite. Fragment Render в этом этапе не изменялся.

В реальном клиенте повторилась потеря листвы в смешанном MDI, хотя прямые вызовы возвращали те же данные. Поэтому режим 3 отправляет только непустые непрозрачные диапазоны через MDI, а двухсторонние модели/листву/воду — отдельным прямым instanced draw. Чисто лиственная страница всё ещё имеет один вызов, смешанная — максимум два. Вариант шейдера с полем гашения снега используется отдельно от обычных моделей. Причина расхождения MDI между синтетическим EGL и реальным клиентом ещё не установлена; это проверенный обход, не заявление об исправлении драйвера.

## Проверка

* `gradlew build --offline --no-daemon --max-workers=2`.
* Все 1024 плитки, 2 627 671 исходный треугольник: проверены восемь независимых source/target комбинаций вершин, неподвижность внешних контуров и совпадение мультимножества оставшихся граней с реальным родителем. [Отчёт](geometry-audit.txt).
* GPU-проверка shipping vertex shader: явная fine-позиция при смещении родителя больше блока, координаты общего поля, temporal release, вариант снегового шейдера.
* Shipping материал + финальный composite: обычный материал, снег и вода получают атмосферу один раз.
* Реальный Minecraft, тот же мир, High Fragment Render, 1280×720, native 8 чанков, LOD 512 блоков. Аппаратного FPS здесь нет: используется llvmpipe. В предыдущем прогоне без boundary cache одинаковый кадр отправлял 2 395 360 треугольников против 2 353 939 у прежнего пакета (+1.8%): уменьшение суммы уровней ещё не доказывает ускорения кадра.

В финальном прогоне на том же ракурсе кэш держал 32 GPU-страницы, из них рисовалась 21. Резидентные буферы backend — 114 697 820 байт (109.4 МиБ) вместо 163 162 672 байт (155.6 МиБ) при загрузке всех переходов. Число отправленных треугольников осталось тем же: кэш меняет резидентность, а не геометрию кадра.

## Воспроизведение

После сборки Vision, с настроенным JAVA_HOME:

```sh
python tools/lod/build_linked_parents.py BASE_PACKAGE SNAPSHOTS OUTPUT
python tools/lod/install_linked_parents.py BASE_PACKAGE OUTPUT NEW_PACKAGE
```

Снимки — сохранённые `b0.fvvol.gz` … `b63.fvvol.gz`, не live save. Проверка исходных/целевых граней автоматически запускается wrapper-скриптом. Публикация сохраняет оригинальные файлы и заменяет manifest атомарно.

В игре: `/voxy mesh load sky-linked-parent -1`. Диагностика: `/voxy mesh`; сравнение с прежним пакетом: `/voxy mesh load sky-native-join-v3 -1`.
