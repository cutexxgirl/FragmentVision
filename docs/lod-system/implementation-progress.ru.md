# Реализация связанного LOD: состояние работ

> Новая проверка и доработка на исходном мире: [Sky_Art_Study, 2026-10-25](sky-art-review-2026-10-25/README.ru.md). Исторические ограничения тестирования ниже относятся к исходной ревизии d8bf9085.

Обновлено 2026-10-25. Это журнал реализации [плана трёх уровней](three-level-runtime.ru.md).
Текущий этап — основа A и минимальная проверка двух соседей из B. Игровой
backend D–H, передача владения Sodium и полноценная смена всех трёх уровней
ещё не реализованы. Тестовый запуск клиента не означает готовность этих этапов.

Отдельно доработан прежний игровой гибрид: достижимы три уровня, добавлены
раннее отсечение заменённых граней и упаковка общей GPU-вершины 80 → 64 байта.
Это не подключение нового QEM-backend. Установлен профиль Sodium 0.8,
Fragment Render со встроенным шейдером, Fragment Grass и оптимизаций; сохранены
уже полученные кадры и результаты Chunky в [отчёте с воздуха](aerial-proof/README.ru.md).
Последняя упаковка GPU-данных не проверена в игре. После просьбы пользователя
не проводить тесты новые проверки и замеры не запускались. Финальная сборка
`assemble -x test` прошла; она не является проверкой игровых шейдеров.

## Добавленный код

- `bake/QuadricSimplifier.progressive`: один проход QEM с историей зависимых
  схлопываний и стабильными исходными ID. Старый независимый baker пока сохранён.
- `bake/ProgressiveMesh`: восстановление любого префикса истории в компактный
  mesh и диагностическая подробная топология во время одной операции. К концу
  операции она совпадает с компактным следующим состоянием, кроме удаляемых
  вырожденных triangles. Исходные arrays принадлежат истории и не выдаются наружу.
- Дополнительный gate для исчезающих shared triangles: положительная ориентация
  по всему интервалу одной операции проверяется аналитически через квадратичную
  ориентированную площадь. Для сохраняемых triangles перемещается одна вершина;
  линейная signed area остаётся положительной при принятых конечных ограничениях.
  Это **локальная ориентация**, не сертификат отсутствия всех swept intersections
  или географической ошибки на всей траектории.
- `runtime/LodWorkQueue`: несколько worker-потоков, priority queue, ограничение
  числа заданий и зарезервированных bytes. Резерв удерживается и после вычисления,
  пока результат не принят/отброшен. Замена pending revision освобождает её резерв;
  работающий устаревший job получает interrupt, его результат не публикуется.
  Перед выдачей результата вызывается внешний предикат актуальности ревизии.
- Проверки отмены в QEM, извлечении поверхности и distance audit. Отмена
  кооперативная; произвольный пользовательский job обязан обрабатывать interrupt.
- `debug/LodClientSmoke`: opt-in интеграционная проверка клиента. Создаёт отдельный
  мир с seed 20261024, постепенно считывает участок на клиентском потоке и передаёт
  законченный snapshot worker. Считывание мира не выполняется из worker.
  Это диагностическое full-cube представление captured states, без конечной
  геометрии моделей и без нового draw-прохода. Snapshot через несколько ticks не
  является production-протоколом согласованных ревизий; он используется только
  в отдельном создаваемом тестовом мире.

Memory reservation — заданная вызывающим кодом консервативная оценка полного job.
Она ограничивает admission/очередь, но не измеряет реальные allocations JVM.
Production manager с проверенным пиком heap/native/GPU ещё необходим.

## Воспроизводимые проверки

```sh
JAVA_HOME=/path/to/jdk21 python tools/lod/check.py
```

К существующим проверкам добавлены:

1. `ProgressiveRuntimeCheck`: зависимая история на холмах, три разных префикса
   **1524 / 942 / 358 triangles**, совпадение начала/конца выбранных одиночных
   переходов, сохранность закреплённых координат и расстояние дальнего состояния
   до оригинала в пределах 1.5 блока. Это **кандидаты**, а не три принятых игровых
   LOD: средние/ближние состояния ещё требуют самостоятельных cost/error gates.
2. Фактический одновременный запуск двух job через barriers; отказ при превышении
   budget, замена ожидающей revision, отбрасывание старой revision, освобождение
   reservations после принятия результата, interrupt работающего задания.
3. `LinkedSeamCheck`: два соседних участка, **9 комбинаций уровней** и промежуточные
   одиночные операции; совпадение открытого общего контура и normals. Стенка,
   лежащая на плоскости раздела и целиком принадлежащая одному соседу, не обязана
   дублироваться вторым: сравнивается общий открытый контур, не все вершины плоскости.
   Пока используются закреплённые решётчатые границы. Это не реализует дальнюю
   упрощаемую face/edge/corner hierarchy или 2×2×2 parent/child stitching.

## Сборка и запуск Minecraft

Полная `compileJava` теперь проходит с Java 21: foojay convention обновлён с
0.8.0 до 1.0.0 для Gradle 9.4.1. Java 25 разрешена пользователем, но этот этап
не требует её возможностей и сохраняет target 21.

Исправлена dev-конфигурация: bootstrap distribution Sodium подготавливается в
`run/mods`, вместо выбора его самого как nested implementation на classpath.
Обычные библиотеки RocksDB/Jedis/codecs/native LMDB/Zstd добавлены в
`additionalRuntimeClasspath` согласно ModDevGradle; одного `implementation`
для обнаружения non-mod библиотек dev-загрузчиком было недостаточно.

```sh
JAVA_HOME=/path/to/jdk21 ./gradlew runClient -PlodSmoke
```

Этот режим автоматически создаёт **новое** сохранение `lod-smoke-<timestamp>`;
существующие карты не открываются. Результат записывается в
`run/lod-smoke-result.json`, ошибка — в `run/lod-smoke-failure.txt`;
снимок обычного игрового мира — `run/screenshots/lod-smoke.png`.
Без `-PlodSmoke` проверка не устанавливается.

В облачном окружении используется Xvfb и llvmpipe. У существующих Voxy shaders
`#version 460`; Mesa по умолчанию заявляет 4.5, поэтому для software smoke используется
`MESA_GL_VERSION_OVERRIDE=4.6 MESA_GLSL_VERSION_OVERRIDE=460`. Это настройка проверки,
не патч шейдеров и не подтверждение аппаратной производительности.
Fragment Render в данном dev-запуске не установлен: доступен только review-снимок
его исходников. Проверка общего материала/теней/атмосферы остаётся отдельным этапом.

## Результат проверки в клиенте

Клиент Minecraft 1.21.1 / NeoForge 21.1.262 / Sodium 0.8.13 загрузил отдельный
мир. Job выполнился в `fragment-lod-worker-0` и вернул результат в клиент.
[JSON проверки](runtime-proof/client-smoke-result.json) и
[кадр обычного мира](runtime-proof/client-smoke.png) сохранены отдельно.
Кадр показывает native/Sodium, **не изображение нового трёхуровневого renderer**.

Финальный изолированный CPU smoke: 455 операций, исходная согласованная сетка
11962 triangles, префиксы 11660 / 11356 / 11052. Но exact packed representation
этого участка — 10700 triangles / 42800 B, а кандидаты —
132568 / 129224 / 125876 B. Все три проиграли собственному exact по бюджету;
**их нельзя включать в штатную отрисовку**. Число исходных triangles здесь
относится к conforming source, не baseline Voxy.

Этот тест выявил ограничение на настоящем лесном участке: общий mesh с
дискретными material/light seams и защитой моделей остаётся дорогим. Требуется
разделение представлений terrain/объектов и атрибутные карты для мелкого света/
рисунка материалов; удалять ключи света или ослаблять защиту ради цифр нельзя.
Полезность трёх уровней по стоимости/качеству пока не доказана.

Первый запуск со старым Voxy terrain draw тоже успел выполнить job, но работа
старого Hi-Z на llvmpipe была слишком тяжёлой для воспроизводимого теста.
В финальном CPU smoke `enable_rendering=false` в отдельной dev-конфигурации:
клиентские события, мир, Sodium и workers работают, старый дальний draw исключён.
Это изоляция проверки вычислений, не полноценный игровой A/B. Изменение настройки
не внесено в исходный default; исходная dev-конфигурация восстанавливается после
проверки. Аппаратной GPU в окружении нет.

## Что делать дальше

1. Подключение версионированного файла истории к manifest/streaming и актуальным world/material revisions. CPU-кодек `ProgressiveMeshFile` уже добавлен при проверке Sky_Art_Study; это не готовый потоковый пакет. Измерить его цену вместе с компактными уровнями и активными переходами.
2. Независимая проверка ошибки всех выбранных состояний и всей траектории;
   проверка swept intersections и ограничений отверстий/защиты. При неопределённости
   сохранять подробную геометрию. Не включать непроверенный morph в штатный draw.
3. Общие упрощаемые face/edge/corner контуры, ограниченные по Y страницы,
   родитель с восемью детьми и проверка углов. Постоянную точную рамку не переносить
   как окончательное решение на весь дальний мир.
4. Реестр актуальных готовых/пустых native sections и согласованная передача
   ownership; затем единственный новый terrain backend и GPU morph активных записей.
5. Streaming, edits/tombstones, ресурсы Render и аппаратная приёмка по основному плану.

Пока нельзя утверждать, что новый QEM-renderer уже работает в игре,
что переход к native готов или что FPS улучшился. Текущий результат проверяет
геометрическую основу и фоновые вычисления в окружении клиента. Отдельный
игровой запуск прежнего гибрида описан выше и в отчёте с воздуха.


## Продолжение: Sky_Art_Study, 2026-10-25

В `ProgressiveMeshFile` добавлен CPU-формат FVPROG01 v1: исходная поверхность,
упорядоченная зависимая история, SHA-256 payload, проверка длины/count/finite
данных и caller-supplied лимит файла до выделения массивов. Атомарная замена
производной страницы выполняется через временный файл на той же файловой системе.
Файловые системы без ATOMIC_MOVE возвращают ошибку; тихого неатомарного fallback нет.
Лимит размера файла не является лимитом всей Java heap: decode/immutable history
используют дополнительные копии, которые production manager обязан резервировать.

Проверено детерминированное кодирование и побитовое восстановление всех потоков
трёх уровней на зависимой истории холмов, плюс replay переходов на малой fixture.
Проверены повреждение, версия/длина/checksum, поддельные counts с корректным checksum,
truncation и превышение бюджета. Подробности игрового запуска и его ограничения:
[отчёт Sky Art](sky-art-review-2026-10-25/README.ru.md).

Кодек не сериализует registry/material manifest, world revision и сертификат
геометрической ошибки. Прочитанная история не считается автоматически принятой
для GPU morph. Runtime интеграция нового QEM-backend по-прежнему не завершена.

В старом HybridTerrain исправлена обработка CompletionException(CancellationException):
нормальная отмена из-за изменения snapshot больше не классифицируется как ошибка.
Время сборки подписано elapsed including queue wait вместо ошибочного CPU.
