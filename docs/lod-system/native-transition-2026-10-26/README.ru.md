# Плавная граница native → LOD: контракт следующего этапа

Статус на 27 октября: первый native → near L0 collar подключён к renderer.
[Результат, проверки и границы реализации](../native-join-2026-10-27/README.ru.md).
Ниже сохранён расширенный контракт для будущего linked перехода к произвольным
упрощённым родителям L1/L2; его нельзя считать целиком выполненным первым near bevel.

## Форма перехода

Для первого прототипа: 2 блока точной геометрии снаружи native, затем 12 блоков
перехода. Длина измеряется в координатах мира, а не в количестве LOD-плиток.
Ширина — настраиваемый бюджет, проверяемый в кадре; увеличение не должно умножать
плотную геометрию на всю дальнюю карту.

1. Граница — объединение действительно готовых и показанных native секций.
   Не квадрат вокруг камеры и не заявленная дальность прорисовки. Для внешней
   поверхности берём готовность соответствующих секций по высоте; для пещер и
   навесов сохраняем отдельное точное представление.
2. Внутри native — один владелец поверхности. Первые 2 блока за границей повторяют
   исходные ступени, боковые грани, UV, материалы и освещение, без смещения вершин.
3. Дальше один скалярный вес `w` меняет координаты от точной поверхности к более
   простой. На обоих концах полосы производная веса нулевая.
4. За полосой остаётся самостоятельный дешёвый mesh. Плотный переход живёт только
   в узкой полосе, не растягивается на все дальние страницы.

Прямой участок: `w = smootherstep((distance - 2) / 12)`.
В углу, где native справа И снизу, нужен общий вес `w = wx * wz`: возле любой
стороны точная форма, в центре угла гладкий переход по обеим осям. `min(wx,wz)`
не подходит: создаёт излом производной по диагонали.

Обобщение на произвольную границу: выделить внешние отрезки объединения ready
ячеек, объединить смежные коллинеарные отрезки, затем перемножать плавные веса
расстояний до тех отрезков, которые находятся ближе внешнего радиуса полосы.
Расстояние берётся до конечного отрезка, а не бесконечной прямой; выпуклый угол
получает округлую область влияния. Внутри native вес всегда 0. Поле непрерывно
с непрерывной первой производной; не суммируем смещения от сторон.

Объединение отрезков обязательно: иначе границы внутренних чанков влияли бы на
форму. Общее поле хранится/обновляется для окружающего кольца, с spatial bins;
не перебирается по всем чанкам для каждой вершины на GPU. Один мировой ключ
границы даёт одинаковые координаты по обе стороны LOD-страницы. Квантуем уже
общий результат, не локальный результат двух независимых решателей.

## Одного веса недостаточно: нужна связанная геометрия

Нельзя интерполировать индексы/вершины двух независимых QEM-мешей. У них разная
топология. И нельзя просто менять только Y: уступы, вертикальные стены, навесы
и отверстия не являются одной картой высот.

Нужна общая детализация переходной поверхности и соответствие fine → parent:

- Сохранить иерархию разрешённых edge collapses при offline bake. Каждая вершина
  перехода имеет исходную позицию и согласованную позицию на родительском mesh.
- Либо строить локальную общую триангуляцию fine/coarse поверхностей, если
  иерархию существующего QEM сохранить не удаётся. Это дороже при подготовке;
  не запускать глобальную ретриангуляцию каждый кадр.
- Переходный collar разрезается по настоящей границе и по концу полосы.
  На внутреннем контуре вершины/рёбра совпадают с native, на внешнем — с parent.
  Shared edge имеет одинаковое разбиение; T-junction не скрывается юбкой.
- `p = mix(pFine, pParent, w)` применим только после такого соответствия.
  Нормаль берётся от деформированной поверхности/её производных. Простой mix
  двух произвольных нормалей способен оставить видимую полосу освещения.
- Проверять переворот/вырождение треугольников и пересечения во всём диапазоне
  перехода. Одних проверок двух конечных кадров недостаточно. Небезопасные
  collapses запрещаются; сложные пещеры/постройки получают точный fallback.
- Снег и ground cap согласуются с геометрией. Не убирать точную снежную оболочку,
  пока переход ещё требует её толщину. Корни деревьев/строения закрепляют
  локальную поверхность либо имеют проверенный контактный переход.

## Три уровня и движение игрока

Переходы native→L0, L0→L1, L1→L2 используют один контракт границ. Соседние
уровни отличаются не более чем на 1. Мелкая сторона владеет переходным collar;
крупная исключает ту же область. Новая геометрия + ownership + материал
публикуются одним поколением, чтобы один кадр не увидел половину обновления.

Ready native учитывает mesh upload/rebuild, в том числе изменение блока игроком.
Прежний LOD не освобождается до готовности замены. При перемещении границы
морф продолжает движение от текущего веса, а не сбрасывается в 0/1. Native
нельзя показывать поверх ещё не совпавшей геометрии; нужны точное перекрытие
на время передачи и согласованная маска владельца, а не произвольный fade.

## Цвет, вода, кроны

Текстуры — исходный atlas и мировые UV; геометрию упрощаем отдельно от материала.
Не смешиваем grass/stone/snow в один средний цвет. Одинаковые функции Fragment
Render для солнца, неба, тумана и biome palette. Проверяем также переход между
областью настоящей shadow map и доступным дальним затенением: геометрия сама
по себе этот световой шов не исправит.

Листва сохраняется отдельными кронами без bushy-плоскостей; цвет, cutout coverage
и видимость проверяются отдельно. Трава/цветы не входят в LOD. Вода — отдельная
поверхность с согласованной высотой и материалом, без морфа вместе с сушей.
Точный берег закреплён; приближение суши не должно подняться выше воды и
закрыть её. Рефракция/пена ближней воды и дальний материал требуют согласования.

## Порядок внедрения и критерии

1. Исправить пропажу крон/проверить воду в текущем backend, сохранив контрольный
   пакет. Считать наличие в snapshot, страницы после bake и итоговую видимость.
2. Реализовать поле перехода и проверки прямой границы, внутреннего/внешнего
   угла, дырки в ready coverage, отрицательных координат и границы двух страниц.
3. На одном участке получить связанный fine/parent collar. Проверить его с
   фиксированной камерой и пролётом; только затем распространить на три уровня.
4. Подключить native-ready ownership с версиями, загрузку/выгрузку и изменения
   блоков. Проверить квадратный и Г-образный стык на траве, снегу и скале.
5. Сравнить всю сцену с Voxy: GPU time, CPU submission, память и число примитивов,
   включая collars и все сохранённые листья/воду. Уменьшение только terrain
   triangles не считается общим выигрышем.

Визуальная приёмка: отсутствие чёткой линии чанков, провалов, наложенных граней,
диагональной складки в углу, скачка освещения и прыжков при движении. На GPU
отдельно ограничивается стоимость collar; если её бюджет превышен, сохраняем
более точный уровень, не снижаем качество текстуры и не скрываем дефект туманом.
